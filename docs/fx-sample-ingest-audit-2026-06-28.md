## 已发现并修复的问题

1. A1P 编码覆盖具体资料类型
   - 问题：第一场所有文件名都带 `A1P260307357`，旧分类器看到 `A1P\d+` 后会把全部图片判为 `a1_meeting_export`。
   - 影响：签到表、现场确认单、PPT、短信、线上截图都会用错视觉 prompt，后续规则会漏关键字段。
   - 修复：A1P 编码只在 PDF/Excel 这类实际导出资料上触发 A1 导出；图片中的 A1P 仅作为会议编号线索。

2. 第二场真实命名覆盖不足
   - 问题：`确认单`、`直播观看数据`、`日程更新报备邮件`、`最大端口数_zoom端`、`其他厂家`、`赞助回报` 原来缺少稳定分类。
   - 修复：扩展合规资料词库；新增 `other_supporting_evidence` 类型，避免重要辅助证据被当普通截图或 unknown。

3. 明确文件名仍低置信
   - 问题：PPT、线上截图、议程、确认单等单关键词文件名原置信度只有 0.70，会触发不必要的 LLM 分类。
   - 修复：明确命名的单关键词命中提升到自动确认阈值，批量导入更稳定。

4. 图片 OCR 后不会纠偏
   - 问题：若用户上传 `image001.jpg` 这类模糊文件名，即使 OCR 文本显示“现场确认单”，旧链路也不会改分类。
   - 修复：视觉 Agent 首轮 OCR 后用 OCR 文本重分类；若分类提升，会用正确资料类型 prompt 重跑一次视觉解析。

## 仍需复核或增强的样本

- 第一场：`签到表 (3).jpg` 分辨率 744x322，质量分约 0.68，需进入补充资料或人工复核。
- 第二场：`会议日程.jpg` 为 864x3889 长图，已标记 `long_image_needs_slicing`，建议做长图切片 OCR。
- 第二场：`沟通短信 (1).jpg` 为 1276x12779 超长截图，已标记 `long_image_needs_slicing`，必须做长图切片 OCR，否则容易漏上下文。
- 两场的确认单/签到类资料均应保留手写风险门控，关键字段低置信时不得自动通过。

## 最高正确率建议

- 导入入口固定为“一场观察案件文件夹”，不要把项目主流程依赖散文件上传。
- 对长图做纵向切片 OCR，再合并时间线和关键事实。
- 对确认单、签到表做字段区域 OCR：会议编码、观察结论、讲者服务时长、签名/手写确认、签到人数。
- 对大量 Zoom/直播截图做分组：Zoom 端、直播端、最大端口数、普通过程截图分开抽取，不应全部按同一字段 schema 处理。
- 所有视觉结果必须输出字段级置信度和复核原因；交付物中保留低置信字段来源。
