# 主 Agent 与记忆架构说明 - 2026-06-28

## 当前结论

系统已经有长期记忆基础，但原来的主 Agent 对话没有充分使用它。现在已调整为：

1. 对话请求进入 `/api/agent/chat`。
2. 后端读取当前项目、子会议、资料、Finding、交付物、最近任务和日志。
3. 后端按用户问题从 `memories` 做相关记忆检索，而不是只取最近几条。
4. LLM 可用时用上下文 + 相关记忆生成回答；不可用时使用可解释的规则回退。
5. 用户明确说“请记住/记住/以后...”时，写入 `user_preference` 长期记忆。
6. 验收、退回、重新分析等高影响动作只返回“待确认动作”，不在对话里直接执行。

## 记忆分层

### 短期记忆

- 来源：当前对话 history、当前页面上下文、当前项目/子会议 live 状态。
- 用途：回答“现在卡在哪”“这场会议为什么待验收”“下一步做什么”。
- 生命周期：本次对话/当前页面，不作为长期学习结果。

### 任务记忆

- 来源：`AgentRunLog`、任务状态、执行日志、工具调用记录。
- 用途：解释链路、排查失败、复盘主 Agent 和子 Agent 做过什么。
- 生命周期：绑定项目/子会议。

### 长期记忆

- 表：`memories`
- 检索：向量 + 标签混合检索。
- 已有类型：
  - `user_preference`
  - `risk_policy`
  - `case`
  - `confirmed_case`
  - `false_positive`
  - `report_template`
  - `accounting_knowledge`
  - `case_example`
- 用途：让后续研判、复核、交付、对话参考历史偏好和案例。

## 会不会越用越聪明

会，但必须是“受控变聪明”，不是无限制记流水账。

当前已支持：

- 复核确认/驳回后写入长期记忆。
- 高置信 Finding 可沉淀为案例记忆。
- 交付反馈可写成政策口径。
- 主 Agent 对话中用户明确要求记住时，写入用户偏好。
- 主 Agent 回答时检索相关长期记忆。

当前已补上第一层“受控自修复入口”：如果用户说“这条不对”“以后遇到这种情况要这样判”，主 Agent 会先判断是否信息足够。信息不足时追问；信息足够时生成待审批的规则学习提案。批准前不会写长期规则记忆；批准后写入 `rule_feedback_policy` 长期记忆，并保留 action proposal 和执行日志。

必须补强：

- 周期性记忆整理：合并重复偏好、删除低价值碎片。
- 记忆置信度/来源：标记来自用户、复核、Agent 自动沉淀或规则导入。
- 记忆作用域：区分全局、项目、客户、会议类型。
- 记忆冲突处理：新偏好覆盖旧偏好时要记录版本。
- 规则修复提案模型升级：从当前 `AgentActionProposal` 扩展成独立 `RulePatchProposal`，包含适用条件、证据字段、预期输出和风险等级。
- 回放评测：规则补丁生效前必须跑 golden cases 和最近相关案件，报告命中变化、误报变化、漏报变化。
- 版本化规则：批准后的记忆口径还需要进入版本化 rulebook，并支持回滚。

## 推荐的自进化闭环

1. 用户反馈：不对 / 不是这样 / 以后应该。
2. 主 Agent 归类：事实纠错、规则口径、输出格式偏好、资料识别问题、一次性本案备注。
3. 不足时追问：适用范围、证据字段、正例/反例、是否全局生效。
4. 生成变更提案：记忆提案或规则补丁提案。
5. 回放评测：至少覆盖当前案件、同类型历史案件、固定 golden samples。
6. 用户批准：显示影响范围和风险。
7. 生效：写入版本化规则/记忆，记录来源和回滚点。
8. 观察：后续命中时显示“依据某条用户批准规则/记忆”。

## 对话化后的架构调整

如果全流程以主 Agent 对话调取，架构必须调整为三层：

### 1. 对话层

负责理解用户意图、解释状态、提出下一步，不直接做高影响动作。

### 2. 动作计划层

把用户意图转成结构化 action：

- `navigate`
- `upload_materials`
- `run_analysis`
- `regenerate_outputs`
- `accept_deliverables`
- `reject_deliverables`
- `search_memory`
- `write_memory`

每个 action 需要有：

- 输入参数
- 影响范围
- 风险等级
- 是否需要人工确认
- 可回滚性

### 3. 执行层

只执行已经校验和审批的 action，并写入日志。

当前已完成：

- `/api/agent/chat`
- 相关记忆检索
- 对话记忆写入
- 高影响动作 `requires_approval`
- action proposal 持久化
- `/api/agent/actions/{id}/approve`
- 前端审批确认组件
- 执行结果回写对话和日志
- 模糊纠错追问：`这条不对` 会要求用户补充正确判法、证据和适用范围
- 受控规则学习提案：明确“以后应该/不能/必须”类纠错会生成 `learn_rule_feedback` 审批动作
- 审批后学习：批准 `learn_rule_feedback` 后写入 `rule_feedback_policy` 长期记忆

下一步应继续补：

- 独立规则/记忆变更提案模型
- 规则补丁回放评测
- 记忆整理任务和冲突处理
- 主 Agent 工具调用从“建议/审批”扩展到“可观察执行计划”

## 产品交互原则

- 左侧栏：只做稳定导航和当前位置。
- 中间区：当前任务的结构化工作台。
- 右侧主 Agent：解释、建议、发起待审批动作。
- 不再把同一动作分散成多个平级入口。
- 高影响动作不能只靠一句聊天直接执行，必须进入审批/确认。
